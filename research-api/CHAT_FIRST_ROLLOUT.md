# SLI Investor Research AI — chat-first release and guarded multimodal rollout (2026-10-18)

## Customer-facing principle
A nontechnical investor writes a plain-language brief such as: "I have IDR 5 trillion and may build an oil refinery in NTB; assess sites, feedstock, permits, utilities, investment risks, employment and multiplier effects." The AI selects an evidence-based methodological plan and produces a sourced research brief, flags missing input, and asks a minimum of follow-up questions. The analyst lab and 49-method list are **optional**, hidden under expandable panels. Nothing on the home screen requires X, Y, FE, AHP matrices or a CSV.

## Production honesty
- **49 methods in catalogue, 7 executable local calculators**: descriptive, Pearson, simple OLS, multivariable HC1 OLS, panel cluster-robust FE, AHP and simple stock-flow. The other catalogue methods are *research design specifications* until their independent numeric executors and QA are built.
- **Input-output/IRIO, CGE/SAM, system dynamics and investor IRR/NPV are NOT performed numerically** by selecting the relevant method. To calculate an economic multiplier, ingest a licensed/authorised official IO or IRIO coefficients matrix and reconcile its year, sector mapping, imported inputs, geographic split and project spend vector. Implement matrix inversion, sector output-to-VA/employment factors, stress tests and independently verified calculations. Distinguish gross output, value added, household income and job-years; never conflate direct/indirect/induced impacts or sum overlapping multipliers.
- **Public generative subscription access remains inactive.** The existing Cloudflare owner-only staging endpoint can create a sourced generative report after a private token is supplied. Deploying GitHub Pages does not deploy a Cloudflare Worker or enable Pro accounts.
- **Optional multimodal owner-upload staging code is prepared but disabled** in `data/sli-research-assistant-config.json` via `owner_test.attachments_enabled=false`. Files MUST NOT be silently sent to an older staging backend that ignores them. The visible file chooser does not mean transmission is enabled.
- Owner testing is limited to 2 files, each <=600 KB; current accepted extensions: PDF, PNG/JPEG/WEBP, DOCX, XLSX, PPTX, CSV, TXT, JSON. Input validation checks the declared extension/MIME, size, and basic magic bytes. These checks alone do not make a potentially hostile document safe; production requires ZIP content/package validation, malware/zip-bomb scans, file isolation, user auth, audit logs, abuse controls, quotas, retention and deletion policy.
- Uploaded data goes to the PRIVATE Cloudflare Worker and, with explicit checkbox consent, can be forwarded to the AI provider. It must be marked **unverified user data**, distinct from licensed SLI sources. Neither a vision description of an image nor model interpretation of an XLSX constitutes a verified numeric regression. Do not upload private or confidential documents without authorisation.
- Charts are currently based on bounded source measurements and chart validators. Full automatic investment maps, return models, executed IO multipliers and polished report packs are **not yet present**. They require new validated, deterministic numeric engines and reviewed data.

## Owner rollout steps (not completed by GitHub Pages deployment)
1. Run all GitHub Actions QA (including `tests/qa-sli-investor-chat.mjs` and `tests/qa-sli-research-conversation.mjs`). Confirm no client secrets are embedded in GitHub Pages.
2. Review Cloudflare limits, model/API document-format support, per-file cost and AI spend cap. Deploy `research-api/src/owner-test-worker.mjs` to the configured owner-only Cloudflare Worker with the existing private secrets (see `OWNER_TEST_SETUP.md`). Do not expose `OWNER_TEST_TOKEN` or `OPENAI_API_KEY` in front-end code.
3. Test exact browser origin and token acceptance, missing consent rejection, oversized/malicious extension rejection, untrusted image/PDF/Office parsing, geographic/sector evidence retrieval, source citations, API errors, no long-term retention of files, and after-request local in-memory cleanup. Use only licensed non-sensitive mock documents for testing.
4. **Only after successful live staging tests**, explicitly set `owner_test.attachments_enabled=true` in the public config and rerun QA. Do NOT enable customer uploads until paid authentication, isolation, rate limits, processing/storage policies and consent records are complete.
5. Separately build trustworthy file-to-structured-data parsers with preview/mapping/provenance checks for Excel/PDF/docx/image. A user upload should join official SLI data only on audited province code, time period, sector, unit and definition; unmatched fields must be explained instead of automatically combined.
6. Introduce capability-discovery/model tool-calling so the AI can invoke only implemented calculators and return numerical artifacts; do not claim it “executes 49 methods” before 49 independent implementations exist.

## Investment research engine target
Flow: **plain-language project brief → infer geography/sector/budget/questions → source retrieval + data permissions → methodology plan → execute authorised calculators if all inputs available → charts/maps + assumptions and limitations → decision-oriented report + versioned evidence**. For the NTB refinery case, start with feedstock/offtake, capacity/technology, land/port availability, electricity/water, environmental and licensing diligence; choose IO/IRIO only after compatible matrices exist. Report any spending amount as a proposed budget, not proof that the project is feasible at that CAPEX.
